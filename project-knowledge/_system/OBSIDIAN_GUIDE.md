# Guia do Obsidian — GoDocs Knowledge

## 1. Abrir o Vault

No Obsidian:

1. escolha **Open folder as vault**;
2. selecione `project-knowledge/`;
3. nome sugerido: **GoDocs Knowledge**.

## 2. Primeira configuração

Começar apenas com recursos nativos.

Ativar quando necessário:

- Backlinks;
- Outgoing Links;
- Graph View;
- Templates;
- Properties;
- Quick Switcher;
- Search.

Não instalar plugins comunitários na fundação.

## 3. Templates

Defina:

```text
templates/
```

como pasta de templates.

Templates iniciais:

- `Zettel.md`
- `MOC.md`
- `Project Note.md`
- `Source.md`
- `Inbox.md`

## 4. Uso diário

### Captura

Criar uma nota em `00-inbox/`.

### Processamento

Ao revisar a Inbox, decidir se a informação deve:

- ser descartada;
- virar tarefa fora do Zettelkasten;
- virar Source;
- virar Project Note;
- virar Zettel permanente.

### Conexão

Ao criar um Zettel, procurar notas relacionadas e adicionar links que expliquem a relação.

### Organização

Adicionar Zettels importantes ao MOC adequado.

## 5. Graph View

O Graph View é uma ferramenta de exploração, não uma meta.

Não criar links artificiais apenas para deixar o grafo mais denso.

## 6. Busca

Usar busca textual e links como mecanismos principais.

MOCs servem como pontos de entrada humanos para áreas importantes.

## 7. Plugins

Plugins comunitários só entram depois que uma necessidade concreta aparecer.

Cada plugin futuro deve ser avaliado por:

- utilidade real;
- manutenção;
- segurança;
- dependência criada;
- compatibilidade;
- possibilidade de resolver com recurso nativo.

## 8. Sincronização

A estratégia inicial é Git.

O Vault acompanha o mesmo repositório utilizado para desenvolvimento.

Não adicionar uma segunda estratégia de sincronização antes de existir necessidade real.
